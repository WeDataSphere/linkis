## 二、变更背景

本版本（LinkisV2.1.4）汇聚 4 条正式需求，分别面向业务接入、可观测性、误操作防护与国产化容器适配三条主线：

1. **企金 MCP 通道接入困难**（REQ-01）：企金 MCP 通道将调用用户统一切换为独立身份 `<user>_ai`，但 `_ai` 用户在 token 体系（linkis_token 表）中无独立记录，token 认证直接失败导致请求被拒。本版本在网关注入 token 降级鉴权能力，`_ai` 用户认证失败时剥离后缀、复用原用户 token 重试一次，从而让 `_ai` 通道无需批量维护 token 记录即可接入。
2. **CS 缓存问题定位困难**（REQ-02）：ContextService 内部使用 Guava Cache 缓存 ContextID → ContextIDValue，但缓存命中率、加载耗时、驱逐原因不可见，KV 读写日志字段不全，线上排查"命中率异常""频繁驱逐""键值写错"等场景缺线索。本版本对 CS 服务全链路补缓存统计、命中/未命中、KV 读写字段与移除原因日志。
3. **数据源误过期风险**（REQ-03）：管理台数据源列表"过期"按钮点击即调用 expire 接口、无二次确认，运维误触导致数据源被误过期、影响下游任务。本版本在调用前增加 Modal 二次确认，降低误操作风险。
4. **国产化容器替换受阻**（REQ-04）：企业版生产要求使用 BES（宝信中间件）作为嵌入式 Web 容器，但 linkis-module 对 Jetty 硬编码依赖，排除 Jetty 后发生 `NoClassDefFoundError`。本版本通过 `@ConditionalOnClass` 条件加载 + JSR-356 标准 WebSocket 解耦 Jetty，使企业版可无感切换 BES，开源版行为不变。

4 条需求在版本登记中均评定为低风险，且均已完成开发与测试归档（versionStatus=completed / ready_to_archive，stage10 回归已通过）。

## 五、关联影响分析

**上游影响**

| 影响对象 | 影响内容 | 处理方式 |
|---|---|---|

| 引擎启动脚本组装（JavaProcessEngineConnLaunchBuilder）——REQ-04 | classpath 追加 BES_PATH | 仅 `BES_PATH` 非空时追加，默认行为不变 |
| 日志解析脚本——REQ-02 | KV 读写日志字段增加 | 向后兼容，旧字段保留，解析脚本适配新字段即可 |

**下游影响**

| 影响对象 | 影响内容 | 处理方式 |
|---|---|---|
| `_ai` 通道任务（jobhistory/引擎拉起身份）——REQ-01 | 降级成功后请求身份保持 `_ai` 用户，引擎仍以 `<user>_ai` 拉起 | 设计决策 Q1 已定：仅凭证降级不改写身份；需 Linux 代理/HDFS/Kerberos 就绪（非本需求开发范围，联调前置留痕） |
| 管理台数据源列表——REQ-03 | 过期操作需二次确认，复用已有 expire 接口 | 纯前端交互增强，后端无改动 |
| BES 企业版部署——REQ-04 | 排除 Jetty 后由 BES 自动接管 Web 容器与 WS | `@ConditionalOnClass` 条件加载，不排除 Jetty 时行为一致 |

## 十一、变更 SOP/Checklist

SOP/Checklist：http://docs.weoa.com/docs/15LjMJe9gUyYNBIj

**发布步骤**

1. 发布类型：灰度发布（isNeedGrayRelease=1），计划灰度日期 2026-10-15；发布环境按第四章批次安排（准生产 → 容灾 → 生产，准生产/容灾 2026-10-20 22:00、生产 2026-10-21 00:00）。
2. 开源版先行（REQ-04）：不排除 Jetty，`@ConditionalOnClass` 全部生效，行为与改造前逐字节一致，无需改启动配置。
3. 企业版灰度（REQ-04）：排除 `spring-boot-starter-jetty`/`jetty-*` 依赖并引入 BES starter，Spring Boot 自动选择 BES 嵌入式容器，重点验证 REST + WebSocket；EC 启动 classpath 追加 `BES_PATH`（非空时）。
4. 网关降级开关（REQ-01）：默认 `wds.linkis.gateway.ai.user.token.downgrade.enable=false`；生产灰度时先在测试环境验证 AC1-AC12 全部，再手动设置 `=true` 开启降级。建议网关降级开关先开或与 MCP 端 `_ai` 切换同时开，避免 `_ai` 请求到达而降级未就绪导致全部认证失败。
5. REQ-02/REQ-03 随包发布：REQ-02 配置 `wds.linkis.cs.cache.stats.log.interval.mills` 默认 30 分钟（非热加载，改需重启 CS）；REQ-03 纯前端交互，随前端包发布即可。
6. 发布窗口：非业务高峰期。

**回滚步骤**

1. 通用配置级回滚：REQ-01 网关开关若开启后出现认证异常率上升，设置 `wds.linkis.gateway.ai.user.token.downgrade.enable=false` 即回滚，`getHotValue` 热加载秒级生效、无需重启网关。
2. REQ-04 回滚：不排除 Jetty 即回退开源版行为，无需代码回滚；`BES_PATH` 不设置即不追加 classpath，EC 行为不变。
3. REQ-02 回滚：将 `wds.linkis.cs.cache.stats.log.interval.mills` 设为 ≤0 关闭统计日志调度（需重启 CS 服务生效）。
4. REQ-03 回滚：纯前端交互增强，回退前端包即可恢复原直接调用 expire 行为。
5. 异常恢复：`@ConditionalOnClass` 条件加载、开关关闭、`mysql` 均保证默认行为不变，回滚时间以配置修改为主（秒级至分钟级）。

## 十二、变更后验证方法

**REQ-01 支持_ai用户鉴权**——上线后验证：

- 功能：开关关闭时 `_ai` 用户请求认证失败（行为与现网一致）；开启后 `zhangsan_ai`（无 token 记录）+ 原用户 token 有效 → 请求放行且身份=zhangsan_ai；原用户 token 无效 → 认证失败无二次重试；非 `_ai` 不触发；动态 token 不介入；热加载关停即时生效；并发独立无串扰。
- 安全：降级日志 token 均为 maskToken 脱敏形态；畸形用户名（`_ai`/`a/b_ai`/`a/../b_ai`/`a b_ai`/`a*b_ai`）均跳过降级；单次重试；身份保持 `_ai`。
- 监控：看网关 token 认证成功率、降级触发次数与成功率（日志关键字 `token downgrade`）、降级失败次数、非降级请求认证成功率（确认无影响）；异常恢复走原失败路径，不产生新错误形态。

**REQ-02 ContextService日志优化**——上线后验证：

- 功能：缓存统计每 30 分钟（默认）输出一次（size/requestCount/hitCount/missCount/hitRate/evictionCount）；SIZE 驱逐走 warn 并提示调优 `wds.linkis.cs.cache.size`；KV 读写日志含 csType/csScope/value/keywords/resultSize/update；create/update ContextID 日志含 csIdType。
- 监控：`scheduleStatsLog`/`printCacheStats` 双层 try/catch，异常不传播、调度不中断；cachedMillis（驻留时长）随移除日志输出，辅助判断缓存容量是否不足。

**REQ-03 管理台数据源失效按钮二次确认**——上线后验证：

- 功能：点击"过期"不直接调接口、先弹 Modal；取消不调 expire；确认调 expire、成功提示"数据源已过期"并刷新列表；中英文文案正确显示；数据源名称为空时 Modal 仍正常展示。

## 十三、其他风险及应对

4 条需求在版本登记中均评定为低风险且无 stabilityRisks 风险必测项；按各需求文档"风险识别"章节汇总风险及应对如下：

| 需求 | 风险 | 应对 |
|---|---|---|
| REQ-01 | 网关鉴权主链路改动（影响所有静态 token 请求） | 开关默认关、仅在失败路径 + `_ai` 后缀窄口触发、AC1/AC5/AC7 兜底、上线前开关 on/off 双态全量回归 token 认证 |
| REQ-01 | 放行身份语义选错导致隔离失效 | 设计决策 Q1 已定：身份保持 `_ai`，仅凭证降级，不改写身份 |
| REQ-01 | token 失效场景降级误放行 / 与 MCP 端开关灰度顺序 | 统一触发、由 CachedTokenService 自判 token 有效性；网关降级开关先开或与 MCP 端同时开 |
| REQ-02 | 日志量增加、KV 读写高频日志噪音 | 统计 30min 一条可接受；KV 日志通过 INFO 级别过滤 |
| REQ-02 | 调度异常未兜底导致调度中断 | scheduleStatsLog + printCacheStats 双层 try/catch，异常不传播 |
| REQ-03 | 二次确认后仍可能误确认（用户责任） | 属用户主观误确认，纯交互增强无业务链路风险 |
| REQ-04 | Web 容器主链路改造 | `@ConditionalOnClass` 条件加载，不排除 Jetty 时行为不变；企业版全量冒烟 REST/WS |
| REQ-04 | `@ConditionalOnClass` 与方法签名陷阱（NoClassDefFoundError） | Jetty 类型仅在方法体内引用，方法签名只用标准类型 |
| REQ-04 | WebSocket 容器间兼容性、EC classpath 变更 | JSR-356 标准支持多容器，企业版重点实测 WS 收发；`BES_PATH` 非空才追加，默认不变 |

结论：本版本 4 条需求均无新增高风险项，主要风险集中在 REQ-01 网关主链路与 REQ-04 Web 容器改造，均已通过"开关默认关/条件加载/默认行为不变/回滚路径明确"等措施收敛为低风险可控；无待人工处置的未决风险（各需求 openRisks 均为空）。
