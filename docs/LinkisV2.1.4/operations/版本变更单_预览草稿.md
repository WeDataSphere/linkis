## 五、关联影响分析

**REQ-01 支持_ai用户鉴权**：mg-gateway 网关层鉴权变更，影响所有经过网关的请求链路。新增 _ai 用户使用旧 token 认证的降级路径，需关注鉴权失败时的回退行为。

**REQ-02 ContextService日志优化**：ps-cs 服务内部日志增强，不涉及外部接口变更，对下游无直接影响。

**REQ-03 管理台数据源失效按钮二次确认**：ps-datasource 前端交互优化，仅影响管理台 UI 操作流程，不涉及后端接口变更。

**REQ-04 XC改造排除jetty/tomcat包**：bes 引擎改造，涉及 linkis-module 核心服务框架重构（Jetty→自定义 Server），影响所有使用 BDPJettyServerHelper 的模块。需重点关注引擎启动脚本（JavaProcessEngineConnLaunchBuilder）适配和 WebSocket 链路。

## 十二、变更后验证方法

### REQ-01 支持_ai用户鉴权
1. 开关关闭：`zhangsan_ai` 携无效 token 请求 → 认证失败（现网行为，无降级日志）
2. 开关开启 + 降级成功：`zhangsan_ai` 携 `zhangsan` 的 token → doAuth 首次失败 → 剥离后缀重试成功 → 请求放行，身份保持 `zhangsan_ai`
3. 开关热加载：不重启网关，false→true→false 切换，行为即时正确
4. 日志检查：token 全程 maskToken 脱敏，含 `token downgrade` 关键字

### REQ-02 ContextService日志增强
1. 触发 ContextID 读写后等待 30min，验证 `ContextID cache stats` 日志输出（size/requestCount/hitCount/hitRate/evictionCount）
2. 触发未命中加载，验证 `Finished to createContextIDValue of ContextID(X), keyValue size:Y, cost:Z ms`
3. 调小 `wds.linkis.cs.cache.size` 制造 SIZE 驱逐，验证 warn 日志含 `cause:SIZE` + tuning 提示
4. 调用 setValueByKey/getContextValue/searchContextValue，验证日志含 csType/csScope/value/keywords

### REQ-03 数据源过期二次确认
1. 点击"过期"按钮 → 弹 Modal，含数据源名称 + "此操作不可恢复"
2. 取消 → 不调 expire 接口
3. 确认 → 调 expire + 提示"数据源已过期" + 列表刷新
4. 中英文切换显示正常

### REQ-04 BES 容器适配改造
1. **开源版（保留 Jetty）**：启动服务 → REST API 正常 + WebSocket 连接/消息收发正常 → 行为与改造前一致
2. **企业版（排除 Jetty + BES）**：启动服务 → BES 自动接管 → REST + WS 正常
3. **中文响应**：触发 SecurityFilter.filterResponse（认证失败）→ 响应体中文无乱码
4. **EC classpath**：设置 `BES_PATH=/opt/bes` → 提交任务 → EC 进程 classpath 含 `/opt/bes/*`
5. **BDPJettyServerHelper API 兼容**：79+ 调用方零改动，gson/jacksonJson/getControllerServer 正常返回

### REQ-05 任务重试支持 StarRocks
1. `linkis.task.retry.switch=true` → StarRocks 任务失败自动重试 1 次，日志含 "The StarRocks task will initiate a failed retry"
2. AISQL/JDBC 任务仍支持重试（原行为不变）
3. 全局开关关闭 → 不重试

### REQ-07 安全工单修复
1. hive 引擎任务冒烟（版本 2.3.3）
2. commons-beanutils 1.11.0 依赖冲突扫描（mvn dependency:tree）
3. JUnit 4.13.2 单测全量执行通过
