## 一、功能概述

### 1.1 功能背景

**当前痛点**：
- 管理员在使用Linkis配置管理功能时，遇到冗余或过期的配置参数无法删除
- 系统仅支持应用和引擎级别的删除（Category级别），不支持单个配置参数（Key-Value级别）的删除
- 随着业务演进，部分配置参数已不再使用，但保留在列表中造成配置冗余

**期望价值**：
- 提升管理员对配置的精细化管理能力
- 减少配置冗余，提高配置可维护性
- 保持配置列表的整洁性和可读性

### 1.2 功能简介

为Linkis配置管理（Setting）模块新增单个配置参数删除功能，允许管理员删除冗余或过期的配置参数（Key-Value级别），实现配置的精细化管理。

### 1.3 适用范围

- **适用用户**：仅限管理员（`isLogAdmin` 为 true）
- **适用层级**：单个配置参数级别（非Category级别）
- **适用配置**：用户自定义配置参数（系统核心参数建议限制删除）

## 二、功能详细说明

### 2.1 用户交互设计

#### 2.1.1 删除入口位置

在每个配置参数项右侧增加删除按钮（Icon）：

```
[配置项名称] [配置Key]     [配置值输入框]  [🗑️ 删除图标]
```

**显示条件**：
- 仅当用户为管理员时显示（`v-show="isLogAdmin"`）
- 删除按钮位于配置参数行的最右侧

#### 2.1.2 删除确认流程

1. **点击删除按钮** → 弹出确认对话框
2. **确认对话框内容**：
   ```
   标题：确认删除配置参数
   内容：删除配置参数 [参数名称] 将会影响用户使用此配置，且不可恢复。

   是否确认删除？
   ```
3. **用户确认后**：
   - 从当前视图移除该配置项
   - 调用后端API删除配置
   - 显示删除成功提示
4. **用户取消后**：
   - 关闭对话框，保持配置项不变

### 2.2 权限控制

| 操作 | 普通用户 | 管理员 |
|------|---------|--------|
| 查看配置 | ✅ | ✅ |
| 编辑配置 | ❌ | ✅ |
| 删除配置参数 | ❌ | ✅ |

**权限判断实现**：
```javascript
// 使用项目中现有的权限判断机制
// storage模块位置: linkis-web/src/common/helper/storage.js

// 获取管理员权限状态（从sessionStorage获取）
import storage from '@/common/helper/storage';

isLogAdmin: storage.get('isLogAdmin', 'session')

// 或者直接使用
isLogAdmin: storage.get('isLogAdmin')
```

**权限来源说明**：
- **后端API**: `GET /jobhistory/governanceStationAdmin`
- **返回值**: `res.admin` (布尔值，true表示管理员)
- **存储方式**: `storage.set('isLogAdmin', res.admin, 'session')`
- **存储位置**: sessionStorage（会话级别存储）

**参考代码** (来自 `linkis-web/src/apps/linkis/view/linkis/index.vue`):
```javascript
// 页面加载时获取管理员权限
await api.fetch('/jobhistory/governanceStationAdmin', 'get').then((res) => {
  this.isLogAdmin = res.admin
  storage.set('isLogAdmin', res.admin, 'session')
})

// 使用时直接获取
this.isLogAdmin = storage.get('isLogAdmin', 'session');
```

**前端UI控制**：
```vue
<!-- 使用v-show控制删除按钮显示 -->
<Icon
  v-show="isLogAdmin"
  type="ios-trash"
  @click="handleDeleteConfig(item)"
/>
```

### 2.3 前端功能范围

#### 2.3.1 支持的删除场景

| 场景 | 是否支持 | 说明 |
|------|---------|------|
| 单个配置参数删除 | ✅ | 本次需求核心功能 |
| 批量配置参数删除 | ❌ | 暂不支持，可后续扩展 |
| 系统核心参数删除 | ⚠️ | 建议后端增加限制 |
| 配置组删除 | ✅ | 已有功能（Category删除） |

#### 2.3.2 不支持的删除场景

- 不支持删除正在被引擎使用的配置参数（需要后端校验）
- 不支持删除全局设置中的核心参数
- 不支持批量删除多个配置参数

**UI变更**：
```vue

  <span class="we-variable-content-label-group">
    <span>{{ item.name }}</span>
    <span class="we-variable-content-label-key">[{{ item.key }}]</span>
  </span>

  <!-- 配置值输入框（现有） -->
```

**事件处理**：
```javascript
methods: {
  handleDeleteConfig(item) {
    // 双重校验：前端再次确认权限（防御性编程）
    if (!this.isLogAdmin) {
      this.$Message.error('无权限操作，仅管理员可删除配置参数');
      return;
    }

    this.$Modal.confirm({
      title: '确认删除配置参数',
      content: `删除配置参数 ${item.name}(${item.key}) 将会影响用户使用此配置，且不可恢复。是否确认删除？`,
      onOk: () => {
        this.$emit('delete-config-item', item);
      }
    });
  }
}
```

#### 3.2.2 Setting组件修改

**接收删除事件**：
```javascript
// 模板中监听删除事件
<variable
  v-for="(item, index) in fullTree"
  :key="index"
  :variable="item"
  @add-item="handleAdd"
  @remove-item="handleDelete"
  @delete-config-item="handleDeleteConfigItem"  // 新增
/>
```

**处理删除逻辑**：
```javascript
methods: {
  async handleDeleteConfigItem(configItem) {
    try {
      // 调用后端API（使用现有的DELETE接口）
      await api.fetch('/configuration/keyvalue', {
        configKey: configItem.key,
        creator: this.currentTabName,
        engineType: this.subCategory[this.currentTabName] ? 
                   this.subCategory[this.currentTabName].categoryName : '*',
        version: '*'
      }, 'delete');
      
      // 前端移除该配置项
      this.fullTree.forEach(tree => {
        const index = tree.settings.findIndex(s => s.key === configItem.key);
        if (index !== -1) {
          tree.settings.splice(index, 1);
        }
      });
      
      this.$Message.success('删除配置参数成功');
    } catch (error) {
      this.$Message.error(`删除配置参数失败：${error.message}`);
    }
  }
}
```

## 四、后端接口设计

### 4.1 使用现有删除接口

本功能复用现有删除接口，无需新增后端API。

#### 4.1.1 接口定义

**接口路径**：`DELETE /configuration/keyvalue`

**请求参数**：
```json
{
  "configKey": "wds.linkis.rm.yarnqueue.memory.max",
  "creator": "LINKISCLI",
  "engineType": "hive",
  "version": "*"
}
```

| 参数名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| configKey | String | ✅ | 配置参数的Key |
| creator | String | ❌ | 应用方（Creator），默认为"*" |
| engineType | String | ❌ | 引擎类型，默认为"*" |
| version | String | ❌ | 版本号，默认为"*" |

**说明**：
- 该接口删除的是配置值（Value），不是配置键（Key）
- 配置键定义保留，仅删除对应标签的配置值
- engineType和version为"*"时表示删除所有引擎类型的配置值

#### 4.1.2 响应定义

**成功响应**：
```json
{
  "method": "/configuration/keyvalue",
  "status": 0,
  "message": "OK",
  "data": {
    "configValues": [...]
  }
}
```

**失败响应类型**：

1. **Key为空**：
```json
{
  "method": "/configuration/keyvalue",
  "status": 1,
  "message": "key cannot be empty"
}
```

2. **参数组合错误**：
```json
{
  "method": "/configuration/keyvalue",
  "status": 1,
  "message": "When engineType is any engine, the version must also be any version"
}
```

### 4.2 权限控制说明

**重要说明**：现有后端接口无权限校验，所有用户均可调用。

**权限控制机制**：
- **前端权限控制**：通过 `storage.get('isLogAdmin')` 判断，仅管理员显示删除按钮
- **后端权限控制**：现有接口无权限校验，所有登录用户均可调用

**安全考虑**：
- 本功能依赖前端权限控制，后端接口不校验管理员权限
- 删除操作删除的是配置值（Value），配置键（Key）定义保留
- 后续可在后端增加管理员权限校验以增强安全性

## 六、非功能需求

### 6.1 性能要求

- 删除操作响应时间 < 1s
- 删除后列表刷新无卡顿

### 6.2 安全要求

**权限控制**：
- **前端权限校验**：使用 `storage.get('isLogAdmin')` 判断，非管理员隐藏删除按钮
- **前端事件校验**：删除方法内再次校验权限（防御性编程）
- **后端权限校验**：现有接口无权限校验，所有登录用户均可调用

**操作安全**：
- 删除操作需用户明确确认（Modal确认对话框）
- 确认对话框清晰说明删除后果
- 删除成功后显示成功提示，失败时显示具体错误原因

**删除范围说明**：
- 删除的是配置值（Value），不是配置键（Key）
- 配置键定义保留，仅删除对应标签的配置值
- 前端列表中移除该配置项（从用户视图移除）

### 6.3 兼容性要求

- 与现有编辑功能兼容
- 与现有高级设置展开/收起功能兼容
- 与配置验证逻辑兼容
