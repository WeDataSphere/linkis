## 二、变更背景

本版本聚焦 Linkis 引擎稳定性与公共服务健壮性两项问题修复：

- **REQ-01 修复 Hive 引擎 Kerberos 认证失败**：开启 Kerberos 认证的集群中，Hive 引擎存活超过 24 小时后出现 TGT 刷新成功但 HDFS 认证失败。根因是 `refreshUgiIfNeeded` 原实现 relogin 后返回新 UGI，但缓存的 FileSystem 实例仍持有旧 delegation token，导致认证失败。本版本改为原地 relogin + 清理 FS 缓存，使 UGI 对象引用不变的同时刷新底层凭证。

- **REQ-02 openfile 拦截防 OOM**：前端控制台通过 openFile 接口分页读取超大结果集时，翻页到 10w 行之后每次请求需从头 skip 数万行并整页装入内存，峰值内存叠加易触发 OOM。本版本新增行数阈值拦截，开关打开时超限翻页直接返回空数据并提示用户，避免服务 OOM。

#### REQ-01 修复Hive引擎kerberos认证失败（[DPMS](http://dpms.weoa.com/#/product/100484/story/detail/555373)）

修改 `KerberosTgtUtils.refreshUgiIfNeeded` 方法：TGT 过期时在同一 UGI 对象上调用 `reloginFromKeytab()` 原地续期（而非返回新 UGI），续期成功后调用 `FileSystem.closeAllForUGI(ugi)` 清理缓存的旧 FS 实例，使后续 HDFS 访问重建 FS 并使用新 delegation token。新增失败计数降级机制：前 2 次 relogin 失败返回原 UGI 降级执行，第 3 次抛 RuntimeException 报错。新增 2 个配置开关，默认关闭，灰度验证后再开启。

- **需求评审：** Kerberos 认证失败根因与修复方案明确，评审通过。
- **设计评审：** 原地 relogin + closeAllForUGI 方案评审通过，并发安全与降级机制已设计。
- **开发评审：** 修改 `linkis-commons/linkis-hadoop-common` 的 `KerberosTgtUtils`，代码评审通过。
- **风险测试验证：** TGT 过期原地续期必测点——需在 Kerberos 测试环境跑 > 24h 验证引擎存活与认证恢复；当前本地回归通过，线上 Kerberos 环境实测结果待部署后验证。

#### REQ-02 openfile拦截防OOM（[DPMS](http://dpms.weoa.com/#/product/100484/story/detail/555374)）

修改 `FsRestfulApi.openFile` 方法：在翻页参数组装前新增行数阈值判定，当 `(page-1)*pageSize` 超过阈值时拦截。开关打开时硬拦截——返回空数据并附带中英文用户提示（`pageLimitExceed`/`display_prohibited`/`zh_msg`/`en_msg`），不走后续读文件逻辑防 OOM；开关关闭时仅打 warn 日志监控放行原逻辑。catch 块兜底确保未预期异常不污染主链路。新增 2 个配置开关，默认关闭。

- **需求评审：** openFile OOM 风险与拦截方案明确，评审通过。
- **设计评审：** 硬拦截 + 降级放行 + catch 兜底三层防护设计评审通过。
- **开发评审：** 修改 `linkis-pes-publicservice` 的 `FsRestfulApi`，代码评审通过。
- **风险测试验证：** openFile 超限拦截必测点——开关 on/off 双状态冒烟通过（提交 SQL → openFile 翻页 → 超限返回空+提示）；并发场景（同用户 ≥3 任务）验证通过。

### REQ-02 发布与回滚

3. **监控指标**：超限翻页 warn 日志数量（开关关闭时）；超限翻页错误返回数量（开关打开时）；publicservice 服务 GC/OOM 事件
4. **回滚条件**：开启后出现正常翻页被误拦或其他 openFile 回归问题
5. **回滚步骤**：设置 `linkis.workspace.openfile.limit.enable=false` → 刷新配置或重启 publicservice
6. **回滚时间**：配置修改 + 服务重启，约 5 分钟
