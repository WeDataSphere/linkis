## 二、变更背景

Linkis 计算治理平台在长期运行中发现，资源管理模块（linkis-resource-manager）存在用户资源展示为负数的异常：引擎异常退出（OOM/超时）、管理员执行资源重置、用户切换引擎标签等场景下，资源释放消息与资源记账之间存在时序不一致，导致已占用资源（used）被扣减为负值、剩余资源（left）超过上限，管理台资源管理页面呈现负数资源，影响运维判断与用户使用。

本版本（LinkisV2.1.5）包含 1 条正式需求 REQ-01「修复资源管理资源展示为负问题」，通过两层机制修复：

1. **O3 引擎退出消息负值丢弃**：引擎退出消息处理时，若扣减后资源为负则丢弃该次扣减操作（识别重置残留 EC 场景，打印 warn 日志），开关控制、默认开启；
2. **OC1 查询展示层归零**：allUserResource/getUserResource 查询出口对 used/left 负数强制归零，并按 left = max - used 重算剩余资源。

两层均通过配置开关控制，关闭时完全恢复原有行为，保证向后兼容。

#### REQ-01 修复资源管理资源展示为负问题

实际变化：后端在 linkis-manager（linkis-application-manager）新增两层资源负值防御——`DefaultResourceManager` 引擎退出消息处理链路在扣减后资源为负时丢弃该次扣减操作（识别重置残留 EC 场景，打印 warn 日志，开关 `linkis.manager.engine.exit.negative.resource.discard.enable` 控制，默认 true）；`RMUtils` 新增 `normalizeNegativeResource` / `normalizeUserResourceVoNegative` / `recomputeUserResourceLeftNegative` 方法，`RMMonitorRest` 的 allUserResource/getUserResource 出口对 used/left 负数归零并按 left = max - used 重算（`negative.normalize` / `left.recompute` 两个独立开关控制，默认 true）。前端 resourceManagement 页面修正展示口径：内存换算小于 1G 的极小残值归零（避免 9.31e-9G 类科学计数法显示）、instances 列取 queueInstances/loadInstanceResource 的 0 合法值不再被 `||` 兜底顶替。

2. 关闭 O3：`linkis.manager.engine.exit.negative.resource.discard.enable=false`，引擎退出消息恢复原有处理逻辑（需重启 linkis-application-manager 生效）。

4. 底层数据一致性：OC1 仅展示层归零，回退不影响数据库资源值与现有调用方；O3 关闭后引擎状态清理（EC 记录删除、标签清理）不受影响。
5. 回滚决策人：运维负责人确认回滚范围并执行。

## 十二、变更后验证方法

变更后按以下步骤验证：

1. 变更完成后在管理台「资源管理」页核对管理员/普通用户资源视图：剩余资源（left）无负值，且 left = max - used 逐字段一致（成功标准：多页抽查 0 负值；失败则回滚至变更前配置）。
2. 观察一次真实引擎退出后的资源扣减：引擎退出消息处理完成后，对应用户 used 资源正确扣减、left 相应回升，不出现负值（成功标准：扣减后各字段 >= 0；失败则关闭 linkis.manager.engine.exit.negative.resource.discard.enable 回退）。
3. 核对 YARN 队列/告警 15 分钟无新增异常告警，管理员与普通用户查询接口均正常返回（成功标准：无新增 P1/P2 告警；失败则按回滚决策树执行）。
